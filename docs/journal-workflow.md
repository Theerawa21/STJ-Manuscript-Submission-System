# กระบวนการวารสาร

เว็บไซต์คงระบบเดิม และเพิ่ม reviewer, peer review, revision, production และ issue/publication ผ่าน GitHub Pages

## เริ่มใช้งาน

1. กองบรรณาธิการเข้าสู่ระบบเดิม แล้วเลือก **เตรียมระบบ**
2. ระบบสำรองฐานข้อมูล/ไฟล์ จำกัดการแชร์ด้วยลิงก์ และเพิ่มตารางเชื่อมโดยไม่เปลี่ยน headers เดิม
3. เพิ่มผู้ทรงคุณวุฒิที่เมนู **ผู้ทรงคุณวุฒิ** และกำหนดความเชี่ยวชาญหลายด้าน
4. ตรวจเอกสารและกลั่นกรอง ก่อนมอบหมายผู้ประเมินอย่างน้อย 2 คน
5. แนบ PDF สำหรับประเมินที่ลบชื่อผู้เขียน ข้อมูลติดต่อ สังกัดที่ระบุตัวบุคคล และ metadata แล้ว ต้องตรวจบทคัดย่อ/คำสำคัญด้วย
6. คำเชิญส่งจากคิวอีเมล reviewer ใช้ลิงก์ที่มีอายุและใช้ครั้งเดียวเข้าสู่ portal ขอลิงก์ใหม่ได้ทางอีเมล
7. เมื่อผลครบ กองบรรณาธิการตัดสินและตรวจข้อเสนอแนะนิรนามก่อนแจ้งผู้เขียน
8. ผู้เขียนส่ง version ใหม่พร้อมคำตอบเป็นรายข้อ ต้นฉบับเก่าไม่ถูกเขียนทับ
9. ตอบรับ → ตรวจ checklist → จัดรูปแบบ → ผู้เขียนยืนยัน Proof → บรรจุฉบับ → เผยแพร่

## ความลับและสิทธิ์

- ทุก endpoint ตรวจ server session/ownership/assignment ไม่ใช้การซ่อน UI แทน permission
- ผู้ประเมินเห็นเฉพาะงานของตนและ blind file ผู้เขียนไม่เห็นชื่อผู้ประเมินหรือ confidential comments
- ไฟล์ต้นฉบับ/review จำกัดสิทธิ์ใน Drive ดาวน์โหลดผ่านบริการของระบบ
- เฉพาะ final PDF และ metadata ของฉบับ Published เท่านั้นที่อ่านโดยสาธารณะได้
- shared editorial account บันทึก actor เป็น EDITOR_SHARED ใช้บัญชีรายบุคคลและบทบาทเพื่อระบุผู้ดำเนินการจริงได้
- ผู้ตรวจภาษารายบุคคลต้องได้รับบทบาทและการมอบหมาย Accepted manuscript ก่อน
- audit อ่านอย่างเดียวจาก UI แต่เจ้าของ Google Sheets ยังมีสิทธิ์แก้ข้อมูล จึงต้องคง backup และจำกัดผู้เข้าถึง

## การแจ้งเตือนและการกู้คืน

มีคิวส่งเมล ประวัติผลส่ง retry/backoff และ dedupe งานอัตโนมัติเรียกทุก 6 ชั่วโมง เตือน 3 วันก่อนครบกำหนด วันครบกำหนด และหลังเลยกำหนดโดยเว้นอย่างน้อย 7 วันต่อการเตือน overdue

กองบรรณาธิการประมวลผลคิวเองได้จากเมนู **ประวัติ / อีเมล** โดยมี confirmation ผลส่งจริงดูในประวัติ ไม่ถือว่าการเข้าคิวเท่ากับส่งสำเร็จ

หาก operation อยู่ใน NEEDS_RECOVERY ต้องตรวจสิ่งที่เขียนสำเร็จแล้วก่อนทำรายการใหม่ ห้าม restore สำรองทับทั้งชุดเมื่อมีข้อมูลใหม่หลัง backup

## การทดสอบ

รัน `node tests/core.test.js`, `node tests/integration.test.js`, `node tests/github-transport.test.js`, `node tests/journal-lifecycle.test.js`

Lifecycle test ใช้บริการ Google จำลอง ไม่มีการเขียนข้อมูลจริงหรือส่งอีเมลถึงบุคคลจริง ทดสอบครบสอง blind reviews, revision versions, confidentiality, acceptance, named proofreader, author proof, issue/publication, download permissions, audit และ email dedupe
